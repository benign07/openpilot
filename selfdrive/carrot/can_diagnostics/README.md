# Carrot HUD CAN 진단

HUD의 **CAN 진단** 버튼 또는 `/diagnostics.html`에서 주행 중 수신 CAN과 설치된 DBC 정의를 비교합니다. 이 기능은 수신 전용이며 CAN 전송, 제어값 변경, DBC 자동 수정 기능이 없습니다.

## 사용 흐름

1. **주행 기록 시작**을 누릅니다. 움직이는 중이거나 오픈파일럿 제어가 활성화되어 있어도 기록할 수 있습니다. 해석된 차량 상태가 없어도 수신 CAN이 있으면 시작하며, 누락된 해석 신호 자체를 기록합니다.
2. 기록은 기기에서 계속되므로 휴대폰 화면을 닫아도 됩니다. 브레이크·방향지시등·사각지대·감속·앞차 상태 변화는 자동 표식으로 남습니다. 동승자는 감속 시작 지연, 강한 제동, 인식 누락 등을 추가로 표시할 수 있습니다.
3. 종료 후 **신호 백과사전**에서 버스·주소·길이별 관측을 확인합니다. **저장 기록**에서 결과와 원시 데이터를 내려받습니다.
4. 선택 항목인 **정차 조작 검증**에서는 브레이크 또는 방향지시등의 조작 전/조작 중/원상 복귀를 3회 반복해 비트 후보를 찾습니다. 이 조작 안내에만 P단·정지·제어 해제·최신 차량 상태 조건이 적용됩니다.

## 기록과 근거

기본 저장 위치는 `/data/community/can_diagnostics/<session-id>/`입니다. 기록을 서버나 GitHub로 전송하지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `raw_can.jsonl.gz` | 수신 CAN의 원래 `logMonoTime`, 수신 시각, 버스, 주소, 바이트 길이, 원시 바이트 |
| `events.jsonl` | 시작/종료, 사용자 표식, 자동 변화, 최대 10Hz의 해석·인식·계획 문맥과 각 서비스의 유효성·시각 |
| `report.json` | 종료 사유, 수집량, DBC 파일 해시, 검증 집계, 반복 조작 후보 |
| `catalog.json` | 알려진 DBC 정의 및 실제 관측의 버스·주소·길이별 목록, 값 범위, 신호 정의·검사 상태 |
| `candidates.csv` | 반복 조작으로 찾은 주소·비트 후보 |

문맥에는 `carState`, `selfdriveState`, `radarState`, `longitudinalPlan`, `carControl`, `modelV2.leadsV3`의 관련 값과 각각의 원래 `logMonoTime`을 보관합니다. 자동 표식은 기존 해석 서비스에서 얻은 보조 근거이며 CAN 의미의 독립적인 정답이 아닙니다.

현행 LX3 HEV의 `CarParams`와 `CanBus`로 버스 범위를 읽고 설치된 파서가 쓰는 DBC를 불러옵니다. 다른 차량이나 런타임 설정 확인 실패는 별도로 표시합니다. 정의의 존재, 바이트 길이 일치, 값 관측, 의미 확정은 서로 다른 상태입니다. 이 버전은 어떤 신호도 자동으로 의미 확정하지 않습니다.

체크섬과 카운터는 **현재 설치된 네이티브 DBC 파서에 설정된 검사만** 수행합니다. 함수가 연결되지 않은 체크섬은 `미검사`이며 성공으로 집계하지 않습니다. 카운터 불연속은 누락된 프레임일 수도 있습니다. 메시지 빈도·최대 간격·기록 말미의 무수신 시간은 관측 통계이며, 차종별 정상 주기 판정은 아직 하지 않습니다. 멀티플렉스 신호는 현재 해석하지 않습니다. 신호 값 통계는 최대 10Hz 표본이므로 순간적인 극값을 놓칠 수 있지만, 원시 CAN은 수신 프레임마다 저장합니다.

## rlog와 별도 비교

같은 기기 부팅에서 만들어진 진단 기록과 겹치는 모든 rlog 구간을 시간순으로 지정합니다. 다음 명령은 openpilot 환경에서 실행합니다.

```sh
python -m selfdrive.carrot.can_diagnostics.compare_rlog \
  --session-dir /data/community/can_diagnostics/SESSION \
  --rlog /data/media/0/realdata/ROUTE--0/rlog.zst /data/media/0/realdata/ROUTE--1/rlog.zst \
  --out /data/community/can_diagnostics/rlog_comparison.json
```

원래 `logMonoTime`별로 버스·주소·길이·바이트와 중복 개수를 비교합니다. 결과는 일치 프레임, 한쪽에만 있는 프레임, 제공한 rlog 시간 범위 밖의 진단 기록을 구분하고 표식을 함께 제공합니다. 누락된 rlog 구간이나 다른 부팅의 로그는 신호 정의 오류의 증거가 아닙니다. 이 도구는 바이트 기록을 대조하며, 주행 제어 성능이나 신호의 물리적 의미를 자동 판정하지 않습니다.

## 자원 제한과 복구

- 주행 30분 또는 압축 전 원시 JSON 512MiB 중 먼저 도달하는 한도에서 종료합니다. 실제 CAN 양에 따라 30분보다 일찍 끝날 수 있습니다.
- CAN이 5초간 끊기거나 여유 공간이 512MiB 미만이면 종료하며 부분 결과를 보관합니다.
- 기존 진단 저장량이 1GiB 이상이면 새 기록을 시작하지 않습니다. 자동 삭제는 하지 않습니다.
- 버스·주소·길이 조합 1,024개, 한 번에 CAN 패킷 128개로 수집 처리량을 제한합니다. 관측 주소/수신 처리 한도 초과는 종료 사유로 남습니다.
- 주행 기록이 없으면 UI가 30초간 연결하지 않을 때 구독 스레드를 종료합니다. 정차 안내 측정은 UI 연결이 15초간 끊기면 종료합니다.
- 웹 서버 재시작 시 수집은 종료됩니다. 전원 손실 같은 비정상 종료에서는 보고서가 없거나 마지막 압축 데이터가 불완전할 수 있습니다.

## 개발 확인

```sh
python -m unittest selfdrive.carrot.can_diagnostics.test_diagnostics
python -m selfdrive.carrot.can_diagnostics --demo --port 7010 --data-dir /tmp/can-demo
```

데모는 화면·보고서에 표시되며, 운영 HUD 경로에서는 활성화하지 않습니다. 로컬 단위/HTTP 테스트는 주행·제어 활성 허용, 정차 안내 조건, 원시 기록 보존, 제한 종료, 비트 순서, 버스 구분, 구성된 검사만 실행, rlog 대조와 다운로드 경로 검사를 포함합니다.

기존 실제 주행 rlog 한 구간(약 72.89초, 450,598 수신 프레임, 633종)을 데스크톱에서 재생해 수집 후 원본과 비교했으며, 모든 프레임의 시간·버스·주소·길이·바이트가 일치했습니다. 이는 수집 및 대조 로직 검증이며 실기기 성능이나 현재 차량 매핑의 정확성을 입증하지 않습니다. 배포 전 실제 환경에서 추가 확인해야 합니다.
