# LX3 HEV 표시 및 수동 차선변경 수정안

이 변경은 검토용이다. 주행 중인 실기기의 제어 소스에는 적용하지 않았다.
진단 웹 화면 개선은 별도 브랜치 `can-diagnostics-20260927`에서 배포했다.

## 수정 범위

- LX3의 순정 `ADRV_0x161.LANELINE_LEFT/RIGHT`를 보존한다. 다른 차종의 차선변경 가능 여부 색상으로 덮어쓰지 않는다.
- `ADRV_0x161`과 `ADRV_0x1ea`의 순정 도로 곡률·좌우 방향을 보존한다. 핸들 각도/3으로 대체하거나 오파 비활성 때 0으로 만들지 않는다.
- 앞차 아이콘 종류/밝기를 상대속도 -0.1m/s 경계 및 radar/vision 출처에 따라 바꾸지 않는다. 유효한 앞차는 제어 활성 시 흰색, 비활성 시 회색이며, 유효하지 않은 거리나 사라진 앞차는 표시를 지운다. 인식·제동에 쓰는 lead 값은 변경하지 않는다.
- LX3의 32바이트 계기판 송신 `0x161/0x162`에 한해 payload 수정 후 체크섬을 재계산한다. DBC 파서의 수신 검증과 Panda 펌웨어는 변경하지 않는다.
- LX3이고 `LaneChangeNeedTorque < 0`인 수동 차선변경 설정에서 한쪽 방향지시등을 켜면 오파 횡제어를 일시 중지한다. 양쪽 신호가 꺼지고 운전자 조향 입력이 없으며 핸들 각도가 15도 미만인 상태가 0.5초 유지되면 기존 제어 경로로 복귀한다. 자동 차선변경 설정, 다른 차종, 순정 긴급 조향 전달은 유지한다.

## 근거와 검증 범위

실기기 소스와 설정을 읽고, 현재 주행의 두 rlog 구간을 로컬에서 분석했다.
한 구간에서 순정 차선값은 좌우 `8/2`, 송신값은 `6/4/2`로 관측되었다.
값 8을 점선으로 추정하는 것은 사용자 관찰과 카메라 차선 형식에 근거하며, 새 DBC 의미를 확정하거나 새로운 표시값을 만들어 보내지는 않는다.

약 73초 구간의 순정 `0x161/0x162` 각 1,450프레임은 기존 Hyundai CAN-FD 체크섬 알고리즘과 전부 일치했다.
같은 구간의 해당 송신 및 송신 회신 프레임은 각 1,450개 모두 불일치했다.
전용 LX3 DBC 이름에 체크섬 콜백이 연결되지 않고, 이 두 주소는 Panda의 체크섬 재계산 버퍼 목록에도 없다.
조향/SCC 등의 `sendcan` 체크섬만 보고 같은 오류라고 판단하면 안 된다. 이들은 Panda 버퍼에서 다시 계산되며, 관측된 송신 회신에서는 검증에 통과했다.

표시·수동 조향 인계 회귀 테스트 19개를 별도 디렉터리에 복사한 수정안으로 실기기 Python 환경에서 실행했다.
메시지 생성은 메모리에서 수행했으며 CAN을 송신하지 않았다. 실제 CANPacker 생성 결과의 체크섬, 비체크섬 바이트 보존, 순정 오류 필드 보존, 다른 차종 동작, 신호 종료 후 복귀, 위험 경고 시 순정 긴급 조향 전달을 검사했다.
정적 검사와 테스트 통과가 실차 체감이나 계기판 렌더링 개선을 입증하지는 않는다.

## 미해결: 최초 차선 이탈 시 경고

현재 주행 로그의 시작부터 카메라 원본 `CCNC_0x162.FAULT_LSS=1`이 관측되고 이후 구간에도 유지된다.
이전 P단 수집에서는 이 오류값이 관측되지 않았다. 현재 확인한 두 구간에는 오류가 처음 올라오는 순간이 없다.
`FAULT_DAS`를 포함한 다른 오류값을 임의로 지우거나 `CanfdDebug`로 경고를 숨기지 않았다.
정차 후 정확한 계기판 문구와 ECU 고장코드, 첫 활성화 전후 로그를 대조해야 한다.
현재 수정안으로 최초 경고까지 해결되었다고 주장할 수 없다.

## 적용 전후 확인

P단·정지·오파 제어 해제를 실제 상태에서 확인하고 원본 백업 및 되돌리기 경로를 준비한 뒤 적용한다.
정차 중 프로그램 로드와 CAN 유효성을 먼저 확인한다. 주행 검증은 운전자가 감독하며 평소의 차선변경과 곡선 구간에서 동승자가 관찰·평가한다.
경고를 재현하려고 고의로 차선을 이탈하지 않는다. 문제 발생 시 기록을 남기고 기존 버전으로 되돌린다.
