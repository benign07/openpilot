LX3 paired authority v3 - development candidate, NOT a vehicle release

Starting point: review/lx3-stock-authority-20261007 at b2d53c1c.
Installed September 27 restored0627/diagnostic seq4 is unchanged.

Scope:
- Actual CRC-qualified bus0 0x10B physical inputs, independent lateral and
  longitudinal authority, exact LX3 profile 190|2048 only.
- Carrot button/configuration decisions cite observed physical release identity.
  Native pending per axis survives separate LFA/SET gestures; MAIN debounce does
  not revoke a later RES grant. Boot AutoEngage alone is not physical permission.
- Versioned paired STATE/epoch transport; universal health v16/CAN v4 retained.
  The v3 companion is 58 bytes; expected/actual size is logged on mismatch.
  controlsAllowed means longitudinal; lateral permission is explicitly reported.
- Admission, OEM-triggered buffered replacement and pre-TXBAR software queue
  checks reject active commands with stale epoch, generation or age.
  An already submitted hardware frame cannot be retroactively cancelled.
- Stock MDPS payload handling and driver-steering coexistence are preserved.
  Real OEM emergency indications flush lateral replacements; OEM traffic is
  counted separately and is never labelled Panda-authorized OP steering.
- Lateral-only monitoring/warnings, scoped event eligibility, and soft-hold
  payload generation are connected to the paired permission rather than a
  command-generates-permission loop.
- selfdrived requests longitudinal authority before its normal enabled state;
  an acknowledged, current-generation grant completes the regular state change.
  Refusal stays asserted until a newer native acknowledgement. A pedal or
  Carrot's internal pause preserves resume eligibility; faults do not.
- Carrot commits automatic hold only after accepted engagement. A real MAIN,
  RES or SET supersedes a pending auto request and cannot inherit its hold.
- LX3 angle startup waits visibly when the measured angle is outside the
  speed-dependent envelope. Once active, a shrinking acceleration envelope is
  approached at the existing jerk/rate limit rather than an instantaneous
  angle jump. This convergence can temporarily remain outside the tighter
  acceleration envelope; the native hard angle and torque limits stay intact.
- Automatic diagnostics record physical event identity, host requests, native
  independent-axis grants/reasons/generations and angle waiting. Heartbeat
  counters do not create full-rate recording edges; existing quotas remain.

Compatibility/behaviour boundaries:
- Other car profiles retain existing control hooks, buffer capacity and two
  reuses. New fields are additive; HUD 1.0.27 APIs are not modified.
- Unknown/mismatched firmware is not silently accepted as legacy parameter190.
- Physical first enable is mandatory; automatic resume requires prior physical
  arming, enabled settings and a post-pedal OFF acknowledgement.
- Soft hold does not independently regain longitudinal permission after revoke.
- OEM fallback is inherited forwarding behaviour; it does NOT guarantee all
  vehicle steering is off. Native active-replacement permission is separate.
- Current angle/torque envelope mirrors host limits; it is not independent
  vehicle dynamics qualification. Actual MDPS/OEM warning causality remains open.

No source OTA, installation, synthetic CAN or vehicle command occurs here.
