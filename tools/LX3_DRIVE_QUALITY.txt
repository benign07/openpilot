LX3 상세 기록 + 영상 평가 / 2026-10-14

목적
출발 대기와 움직인 뒤 가속을 구분하고, 주행 설정이 계산에 영향을
주었는지 실제 영상과 함께 검토한다. 주관적 편안함/플라시보를 자동
확정하거나 운전 설정을 자동 변경하는 시스템이 아니다.

차량 기록
- LX3에서만 기존 plannerd/logMessage/rlog 경로를 사용한다.
- 정지/약22km/h 미만/감속 또는 접근억제 중에는 planner 매주기,
  일반 순항에서는 4주기마다 기록한다. nominal planner는20Hz다.
- 실제 적용 설정, 입력 원래시각/유효성/생존, 정지유지/출발허용,
  가속 상한 단계, 필터 상태, 앞차 ID/거리/상대속도, MPC 출력과
  유연화의 상태·반환이유를 기록한다.
- 같은 필터 상태로 TrafficCalm30/40의 양의 가속 상한만 비교한다.
  비교값은 명령이 아니며 차량으로 송신하지 않는다.
- 상한이 다르거나 매20주기에는 이미 계산된 MPC 입력·출력 배열을
  복사한다. 두 번째 차량 내 MPC나 추가 CAN 송신은 없다.
- 판다/MDPS/조향/운전자 공존/DisableDM/브레이크 조건을 변경하지 않는다.
- 기존 longitudinalPlan 발행 뒤에 상세 로그를 직렬화한다.
  빌드5ms 초과 시 그 기록을 건너뛰고20주기 쉬며 누락을 기록한다.
  이는 실행시간의 hard real-time 보장이 아니다. 기존 MPC 입력 배열
  복사 시간도 기록한다. 프레임은32KiB 이하로 제한한다.
- DEBUG는 기존 logmessaged의 INFO 디스크 회전로그에 쓰이지 않는다.
  rlog에는 저장되고 qlog에는 들어가지 않는다. 기존 loggerd 보존정책과
  업로드 설정은 유지한다. 자동진단의512MiB quota/손실 표시도 유지한다.
- 새 종류는 기존 자동진단 chunk에 추가되므로 기존 HUD/휴대폰-PC
  전송 계약을 유지한다. 앱 업데이트는 필요하지 않다.

PC 평가
python tools/lx3_drive_quality.py --input <수집폴더> --out <평가폴더> --video
추가 수집폴더는 --input을 반복한다. rlog 읽기에는pycapnp/zstandard,
영상에는ffmpeg/ffprobe가 필요하다. --schema-dir로 해당기기스키마를 지정한다.

평가폴더의index.html을 열면 재출발/가감속 변화/차선 편차 추정/오파
경고 지점에서 영상을 확인할 수 있다. 영상은 로컬 qcamera를 MP4로
재포장하며 원본을 변경하지 않는다. encoder presentation index와
실제 MP4 PTS를 매칭한다. 프레임 수/시계 매핑 불명확 시 미연결로 남긴다.
운전자 평가는 버튼으로 추가하고drive_feedback.json으로 저장한다.
평가자료/위치/원본영상은 GitHub에 올리지 않는다.

report.json에는 실제 입력파일 SHA, 파일읽기/영상매핑 오류, 0.1초
가속도중앙값으로부터 계산한jerk분포, 차간시간, 모델차선중앙추정 편차,
재출발 단계와 누락·페달·제어취소·앞차교체 등 비교제외 사유가 남는다.
차선중앙 추정은 실제 차량 위치의 정답이 아니며 보정/곡률/인식 영향을
받으므로 영상을 반드시 함께 확인한다. 임계값은 검토 후보 추출용이다.

설정 효과 분류
- 기록 부족/설정 변경/누락/오래된 입력: unknown.
- 동일 상태에서 상한 동일: same_ceiling_on_recorded_inputs.
  이것은 전체 계획 동일성이나 플라시보 증명이 아니다.
- 상한 차이: different_ceiling_not_yet_proven_command_effect.
- --native-pair는 PC의 실제Acados가 있을 때 제한된 단일문제를 비교한다.
  acc/nonreset/양의 설정속도/추가거리참조 없는 경우만 지원한다.
  양의 상한과 cruise obstacle을 함께 재계산하고 물리 앞차/정지 장애물은
  유지한다. 이전 primal 해만으로 초기화하므로 내부 dual/warm state와
  같다고 주장하지 않는다. 기준재생이 실제 해/목표/정지판정과 맞지 않으면
  baseline_mismatch로 남기며 효과 수치를 채택하지 않는다.
  통과해도 단일 계산 차이이지 다른 설정으로 실제 운행한 결과가 아니다.

운영
PC에서 검증 후 서명된 HUD 소스 OTA로 공개한다. 공개/설치/실차검증은
별도 상태다. 차량 설치는 새 P/속도0/제어OFF 확인 뒤에만 수행한다.
이미 준비된 SPI native 후보는 별도이고 이 소스 OTA에 포함하지 않는다.
